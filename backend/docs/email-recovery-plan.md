# Email и recovery: план локальной реализации

Ограничения: файлы только в FinanceApp, Docker разрешён, CI/внешняя отправка писем не используются.
V1/V2 не редактируются. Новые изменения — V3/V4.

## Email

- Регистрация возвращает 201 без токенов. Пользователь подтверждает email одноразовым
  токеном, затем входит обычным login. Старые неподтверждённые аккаунты проходят resend.
- Verify TTL 24 часа, reset TTL 15 минут; CSPRNG 256 бит, в БД только SHA-256.
- Request/resend/forgot — одинаковый 202 для неизвестного/disabled/неподходящего аккаунта;
  SMTP не блокирует HTTP. Cooldown 60 секунд на аккаунт/назначение, глобальный IP limiter сохранён.
- Письмо ставится на ограниченную RAM-очередь после commit; при ошибке доставки можно
  повторно запросить письмо. Реальный SMTP adapter, локальные тесты с Mailpit без внешнего relay.
- Reset одноразовый: пароль и отзыв всех семей/токенов меняются одной транзакцией.

## Recovery epoch

- UUID epoch обязателен в sync-запросе и сохранённой outbox-операции. Старые значения
  отвергаются до чтения idempotency или изменения данных, даже при совпавшем числовом cursor.
- Backup не архивирует текущую epoch и незаконченные recovery-сеансы. После restore
  сервер создаёт новую epoch в MAINTENANCE и отзывает старые auth/action tokens.
- Администратор выполняет prepare/status/activate с отдельными DB credentials.
  Activate требует сверки восстановленных данных и удалений; это не автоматическое
  восстановление подтверждённых после snapshot операций из отсутствующих данных.
- Устройство получает replay журнала от 0 до фиксированного cutoff, сохраняет
  локальную recovery-копию (включая подтверждённые записи и pending), изолирует старый
  outbox и подтверждает завершение. До ack обычный push/pull запрещён.
- После ack разрешены только операции текущей epoch. Старые pending нельзя просто
  пометить новой epoch: reconciliation создаёт новые operationId после явной проверки.

Проверки: expired/reused/purpose-mismatched tokens, anti-enumeration, гонки reset/login,
отзыв семей, неизменность старого outbox, stale epoch, неполный replay/ack, разные
устройства/аккаунты, rollback старого snapshot и настоящий локальный restore drill.
Android-клиент в проекте отсутствует: его обязательная последовательность и ограничения
сохраняются в контракте, сервер проверяет epoch и состояние handshake.
