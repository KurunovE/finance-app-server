# Этап 1: схема и изоляция PostgreSQL

Пользователь разрешил переход к этапу 1 и исключил запуск CI.
Файлы изменяются только в FinanceApp; проверки используют Docker.

1. Bootstrap создаёт отдельные роли finance_migrator / finance_runtime и схему app.
   Пароли поступают из окружения, в миграциях их нет. Существующие тома не удалять.
2. Flyway под migrator создаёт 10 таблиц из раздела 6 ТЗ, ограничения и индексы.
   Используется user_sync_state, как в разделе схемы. Никаких начальных пользователей
   или общих категорий в миграции.
3. ENABLE/FORCE RLS на семи финансовых и sync-таблицах, default deny без контекста.
   Runtime не владелец, не superuser, без BYPASSRLS, CREATE, TRUNCATE и членства в migrator.
4. Helper устанавливает verified UUID один раз внутри активной JDBC-транзакции.
   Проверки на реальном пуле из одного соединения: commit, rollback, read-only,
   чужие INSERT/UPDATE/DELETE, составные FK, CHECK/UNIQUE, атомарность регистрации.
5. Полный clean check bootJar, отчёт JaCoCo >=80%, форматирование через IDE,
   документация запуска и фактический отчёт. Новые REST-маршруты — следующий этап.

Критерии приёмки: DB-01/02, ISO-03/05/06/07 и ограничения схемы из ТЗ.
Auth-таблицы пока без RLS согласно ТЗ; их доступ в коде будет ограничен auth-слоем
этапа 2. RLS защищает от забытых фильтров, но не от скомпрометированного runtime
или SQL injection, способных установить произвольный app.current_user_id.
